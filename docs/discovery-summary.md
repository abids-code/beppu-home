# Beppu Home — Public Website Discovery Summary

- Site audited: https://www.beppuhome.jp/ (株式会社別府ホーム, Beppu / Oita, Japan)
- Audit date: 2026-10-28 (content snapshot as observed on that date)
- Method: read-only, unauthenticated HTTP GET requests (curl, roughly 1 request per second), HTML parsing with the Python standard library, and reading the site's own public JavaScript files. No forms submitted, no logins, no anti-bot bypass, no server access, no changes to the live site.
- Outputs: `page-inventory.csv`, `content-inventory.md`, `asset-inventory.csv`, `url-redirect-map.csv`, `owner-verification.md`, this file.

## 2. Discovery method and coverage

1. **robots.txt**: `User-agent: *` with no `Disallow` rules. It references `http://www.beppuhome.jp/sitemap.xml` (HTTP, not HTTPS).
2. **sitemap.xml**: 28 URLs: homepage (1), service/company pages (8: buy, buy/inheritance, buy/flow, any, company, investment, homestaging, performance), listing pages (2: column, property), news posts (15: `column/post-1` to `post-15`), and property pages (2: `property/post-13`, `property/cate_1`). The file was generated by a third-party sitemap generator, and its `lastmod` values are from 2021–2022.
3. **Homepage and nav**: internal links, footer links, and in-page CTA links were extracted and resolved to absolute URLs.
4. **Link-following**: every sitemap URL was fetched once. Discovered internal links that were not in the sitemap were then checked.
5. **Pagination**: `/column/` links to `?p=2`. That page links to `?p=1` and `?p=3`. `?p=3` contains no posts. This exposed 20 news posts that exist only in the listing, not in the sitemap.
6. **Dynamic content**: the homepage loads its "latest 3" news and property cards via JSONP calls to `./column/_custom/?limit=3` and `./property/_custom/?limit=3`. **I did not call those endpoints.** They are undocumented internal endpoints, and the same content is covered by the static listing pages.
7. **Third-party links** (not crawled): LINE (`line.me`, `page.line.me`), athome (`www.athome.co.jp`), Google Business (`g.page`), Oita Prefecture (`www.pref.oita.jp`), Beppu tourism (`beppu-tourism.com`), karin-oita (`karin-oita.com`), zennichi (`oita.zennichi.or.jp`), B-biz LINK (`www.b-bizlink.or.jp`), and one Yahoo search link and one `www.nagatomi.co.jp` link. Each was recorded, not followed.

## 3. Inaccessible or unverified pages

- **Inaccessible**: none. Every discovered HTML URL returned 200 with HTML.
- **Unverified in a rendered browser**: all content was read from the server-rendered HTML. I did not run a headless browser, so JavaScript-only rendering, slider/carousel states (slick.js), and animation-hidden text were not visually confirmed. Text inside slider markup is included in the HTML and was extracted.
- **Unverified dynamic content**: the homepage "latest news" and "latest properties" cards (populated by the JSONP endpoints above) were not captured directly. They are assumed to mirror the first 3 items of the static listings.
- **Not crawled by design**: third-party sites, external maps, the 3D tour (`my.matterport.com`), and the contact form's CGI endpoint.

## 4. Duplicate content

| Duplicate | Evidence | Recommendation |
|---|---|---|
| `/column/?p=1` vs `/column/` | Byte-identical (27,121 bytes each) | Serve one URL; redirect `?p=1` to `/column/` |
| `/performance/index.html` vs `/performance/` | Both return 200. Not byte-compared. | Keep one canonical URL |
| `http://www.beppuhome.jp/` vs `https://www.beppuhome.jp/` | `http` returns 301 to `https`. Old pages link to `http://www.beppuhome.jp/` (115 link references). | Use HTTPS only; update internal links |
| Footer copyright line | Shown twice on most pages (`Copyright c 株式会社別府ホーム . All Rights Reserved.`), and the © symbol is missing | Single footer, correct © |
| Trailing slash vs none | `/any` and `/buy` 200 and redirect to `/any/` and `/buy/`. Old internal links use both forms. | Canonical trailing-slash form |
| Address/phone blocks | Repeated in header, footer, and body on most pages | Expected; keep as shared components |

No `<link rel="canonical">` tag exists on any of the 52 pages.

## 5. Missing translations and language gaps

- **No English site exists.** All 52 pages declare `lang="ja"`. There is no `hreflang`, no English URL, and no English content in the body copy.
- **English section labels only**: about 20 short English labels appear as decorative headings (for example "SELL YOUR PROPERTY", "SHORT SALE", "INVESTMENT・HOLIDAY HOME", "CONTACT US", "Why Us?"). These are not translations and should not be treated as English content.
- **Explicit English-speaking claims**: `/investment/` and `/company/` describe the representative as a native English speaker and offer English-language service. No English page supports that claim, so the owner should confirm what English service is actually offered.
- The brief requires Japanese and English content recorded separately. Only Japanese was found, so **no English content inventory was produced**. Nothing has been translated or invented.

## 6. Broken links and soft errors observed

1. **Broken internal link (confirmed)**: `/property/cate_1/` contains `<a href="./post-13/">`, which resolves to `/property/cate_1/post-13/`. That URL returns **302 → http://www.beppuhome.jp/** (homepage). Users are silently sent to the homepage.
2. **Soft 404 (confirmed)**: unknown paths such as `/this-page-should-not-exist-404-check/` return **302 → http://www.beppuhome.jp/**, not 404. Search engines and link checkers cannot detect broken URLs. This also hides broken internal links.
3. **Redirect chain**: `http://…` → 301 `https://…` → (for unknown paths) 302 `http://…` → 301 `https://…`. The redirect target for soft-404s uses HTTP.
4. **Pagination link**: `column/?p=2` is linked as `./?p=2`, which works, but the pagination has no `rel="next"`/`rel="prev"` tags.
5. **Stale sitemap**: 24 live URLs are missing from `sitemap.xml` (20 news posts, `/contact/`, and 3 pagination views).
6. **Links that resolve correctly but are misleading**: `/buy/flow.html` and `/buy/inheritance.html` are old `.html` URLs. They return 200 and should redirect to the extensionless path in the new site.

## 7. Operational issues noticed (not in the brief, recorded for the owner)

- `<meta name="viewport" content="width=device-width, initial-scale=-100">` appears on all 52 pages (shared template). The `initial-scale=-100` value is invalid and may break mobile layout; this needs a rendered phone-width check.
- Google Analytics Universal Analytics ID `UA-145228358-9` and Google Tag Manager `GTM-N8JRLZX` are loaded on every page. Universal Analytics stopped processing data in 2023, so the analytics setup needs an owner decision.
- No `<link rel="canonical">`, no `hreflang`, and no `og:` Open Graph tags were found in the parsed head sections.
- The homepage includes a LocalBusiness JSON-LD block. Other structured data present: BreadcrumbList on most pages, HowTo + FAQPage on `/buy/flow.html`.
- Image alt text is present on nearly all content photos. Three image references have empty alt text; one HEIC photo (`column/_data/.../6_1_2.heic`) will not display in most browsers.
- The privacy policy and terms of use are inside `/company/` (not as separate pages). Their legal accuracy and whether they are the current versions need owner or legal review.

## 8. Limitations of this audit

1. **Single snapshot**: content observed on 2026-10-28 only. No history or archive comparison was done.
2. **Server-rendered HTML only**: no browser rendering, no JavaScript execution, no screenshots, no mobile rendering check.
3. **Text extraction**: the body text came from a generic HTML parser. Table layouts (fee tables, the performance list) were flattened, and some line breaks and emphasis were lost. Check against the rendered page before reproducing.
4. **Assets**: 19 of 180 asset URLs were HTTP-checked. The other 161 were classified by filename and HTML context only, and their availability was not verified.
5. **No property price or full specifications** were visible in the HTML. The single property listed (`post-13`) has a gallery, a floor plan reference, a Matterport tour, and a map, but no price field.
6. **Dynamic lists not called**: the JSONP endpoints (`_custom`) were not called, so any content only available there (for example items beyond the static listings) is unknown.
7. **Scope boundary**: this audit covers public, unauthenticated pages only. It does not cover the CGI backend, the database behind the property listings, the owner's Google Business profile, LINE account content, or any third-party listing sites.
8. **Crawl mistakes disclosed**:
   - The first full re-crawl re-fetched 15 URLs (`column/post-1` to `post-15`) that had already been fetched. The data was identical, and the extra requests were about 15.
   - A link-checking script resolved some relative links against the wrong base path. Of its 46 checks, 37 requested paths that do not exist on the site (`/post-1/` to `/post-35/`, `/cate_1/`, `/property_cate_1/post-13/`), and 9 requested valid aliases. The 37 bad paths returned the homepage redirect. The real links were then re-checked correctly (see §6).
   - One HTTP check on `http://www.beppuhome.jp/` and one on `/column/?p=1` were made to confirm behaviour.
9. **Rate and load**: about 145 total requests over the audit, at roughly one per second, with no parallel requests and no retries on failure. Breakdown: sitemap/robots/homepage 3, page crawl 29, re-run of 35 post URLs 35 (15 of them repeats), pagination views 3, two JavaScript files 2, link checks 46, URL behaviour tests 5, image HEAD checks 19, and misc 2. The only downloads beyond HTML were two small JavaScript files (`js/top.js`, `js/common.js`) and 19 HEAD requests on images.
10. **Contact form**: the form's field names and labels were recorded from HTML. The form was not submitted, no customer data was entered or collected, and the CGI endpoint was not called.
11. **Personal information**: the representative's name, a staff photo, and transaction case details (locations and building names in news posts) appear on the public site. They were recorded in the inventory only because they are already published. Their reuse requires owner approval (see `owner-verification.md`).

## 9. Recommendations before the next step

1. Owner reviews `owner-verification.md`. Several claims and fields need confirmation before copying them to the new site.
2. Decide the new URL structure. `url-redirect-map.csv` proposes keeping current paths and normalising `.html` and `?p=` URLs, but nothing is approved.
3. Decide English-language scope. There is no English content to migrate.
4. Confirm rights to all images (`asset-inventory.csv`). Nothing should be reused without permission.
5. Re-run the discovery against the rendered site (with a browser) before implementation to confirm JavaScript-only content.
